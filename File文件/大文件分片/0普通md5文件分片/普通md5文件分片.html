大文件分片（普通md5版）

    
当前代码存在的两个核心问题：

        问题一、普通的md5() 函数不支持 ArrayBuffer：
        普通的 md5.js（如 blueimp-md5）的 md5() 方法期望接收的是字符串。
        当你把 ArrayBuffer 传给它时，它依然会将其强制转换为字符串 "[object ArrayBuffer]"，导致每个文件切片blob的哈希值都变成了相同的值。
       
        问题二、Promise.all 并发导致主线程崩溃：
        如果文件有 1GB，分片大小(CHUNK_SIZE) 是 5MB，那么 总分片数(chunkCount) 就是 200。
        Promise.all 会瞬间发起 200 个 FileReader 和 200 次 MD5 计算。虽然 FileReader 是异步的，
        但 MD5 哈希计算是极其消耗 CPU 的同步操作。这会瞬间占满浏览器主线程，导致页面完全卡死甚至崩溃。
