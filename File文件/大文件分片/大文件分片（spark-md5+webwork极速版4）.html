🔍 核心代码解析：
1、Worker 依然保持纯粹：
Worker 内部依然只返回 { index, hash, success: true }，绝不把 Blob 传回主线程，保证了计算阶段的丝滑流畅。

2、主线程按需切片：
在 startUploadChunks 函数中，当需要上传第 index 个分片时，主线程使用 currentFile.slice(start, end) 重新生成一个 Blob 对象。
注：file.slice() 在浏览器底层只是创建了一个指向原始文件的内存视图（零拷贝），所以即使多次调用，也不会导致内存翻倍。

3、并发上传控制：
代码中加入了 MAX_CONCURRENT_UPLOADS = 3 的并发控制。如果文件有 100 个分片，浏览器会同时发起 3 个上传请求，当一个完成后，再自动触发下一个。这能有效防止瞬间发起上百个请求导致浏览器崩溃或服务器拒绝服务。
